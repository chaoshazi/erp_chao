# 人工验收用例清单（AI 能力层 + 自研 ERP）

给业务方与验收人用。每条都写清「怎么操作、期望看到什么」，跑完在结果列打勾。

自动化用例（ERP 103 条、AI 层 237 条）守的是接口契约、算法与回归，守不了「界面上看起来
对不对」，所以这份清单不能省。两者都过，才叫验收通过。

## 0. 验收前提

- 三个进程组都起来了（Ollama 向量 → ERP 9200 → AI 层 8000），顺序见 runbook.md §3。
- ERP 用干净库：首次启动时 `ERP_SEED_DEMO=true` 会写入演示数据。
- 账号见 runbook.md §4：

| 身份 | 账号 | 角色与团队 |
| --- | --- | --- |
| ERP 管理员 | `admin@example.com` / `admin12345` | 全量数据 |
| 陈晓 | `chenxiao@example.com` / `sales12345` | u-100，manager，t-purchase |
| 周敏 | `zhoumin@example.com` / `sales12345` | u-200，staff，t-sales |
| 李娜 | `lina@example.com` / `sales12345` | u-300，manager，t-finance |

- AI 控制台**没有登录页**：身份在「设置」面板里带 —— `API 地址`（同源留空）、
  `X-User-Id`、`X-Team-Ids`、`X-User-Admin`、`访问令牌`（对应 `AICRM_API_TOKEN`）。
- F 组会改数据，建议放到最后跑，或跑完重建 ERP 库（删掉 `D:\erp\data\erp.sqlite3` 重启）。

## A. ERP：登录与权限

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |
| A1 | 用管理员账号登录 ERP 前端 | 进入控制台，能看到全部对象与全部记录 | ☐ |
| A2 | 用 `chenxiao@example.com` 登录 | 采购侧可见：`po-0001` / `po-0002`、`sup-*`、`item-*` | ☐ |
| A3 | 用 `lina@example.com`（u-300，t-finance）登录 | 只看到本队记录：`cus-0002`、`so-0002`、`inv-0001`、`inv-0002`；采购单与物料**看不到** | ☐ |
| A4 | 用错误密码登录 | 提示「邮箱或密码不正确」，不泄露账号是否存在 | ☐ |

A3 是行级权限的关键用例：看不到不是接口坏了，是权限生效。

## B. ERP：业务界面与口径

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |
| B1 | 打开物料列表 | `item-0001` 余额 0，低于安全库存 20，属于低库存 | ☐ |
| B2 | 打开统计总览 | 采购额 111750、销售额 108800、库存值 34400、应收 76800、应付 86000、低库存 1 条 | ☐ |
| B3 | 打开采购单 `po-0002` | 能看到供应商 `sup-0002` 与采购行 `pol-0003` | ☐ |
| B4 | 抽查任意一条销售单 | 客户、金额、状态与采购/库存流水对得上 | ☐ |

注意 `GET /api/v1/stats/overview` 的返回是**顶层键**（没有 `{data: ...}` 信封），
列表类接口才是 `{data, next_cursor, total}`。对接口时别按信封去取。

## C. ERP：接口行为（契约与安全）

```powershell
$h = @{ Authorization = 'Bearer dev-service-token' }   # 服务令牌，生产环境换成真值
$b = @{ 'Idempotency-Key' = 'acc-0001' }
Invoke-RestMethod -Uri 'http://127.0.0.1:9200/api/v1/purchase_orders/po-0001' -Headers $h
```

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |
| C1 | 不带 `Authorization` 调 `/api/v1/items` | 401，不是 200 | ☐ |
| C2 | 用销售账号去改采购单（越权） | 404 —— 越权与不存在统一返回 404，不泄露记录存在性 | ☐ |
| C3 | 同一个 `Idempotency-Key` 重放同一个写请求 | 第二次不产生新记录，`version` 不变 | ☐ |
| C4 | 带上过期的 `version` 提交更新 | 409，提示版本冲突 | ☐ |
| C5 | 打开 `/api/v1/audit` | C3 / C4 的操作都留了痕，含 `actor_id` / `actor_kind` / `source` | ☐ |

## D. AI 能力层：同步与问答

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |
| D1 | 「同步」面板点全量同步 | 11 个对象、`failed=0`；演示库 28 条记录、28 个检索块 | ☐ |
| D2 | 提问「PO-2026-0002 现在什么状态？」 | 答案带 `[erp:po-0002]` 一类引用，`degraded=false`，状态可回溯到单据 | ☐ |
| D3 | 问一个资料里根本没有的问题 | 明确说资料里没有，不编造（引用白名单校验生效） | ☐ |
| D4 | 把 `X-User-Id` 改成 `u-300`、`X-Team-Ids` 改成 `t-finance`，再问 D2 的问题 | 答不出采购单（ACL 生效），或只答本队数据 | ☐ |
| D5 | 打开「健康」面板 | `embedding_ok=true`、维度 1024、`llm_mode=live`、数据源是 ERP、MCP 状态可见 | ☐ |
| D6 | 用流式问答问一句长问题 | 打字机效果正常，`degrade_reason` 为空（不再降级成原文片段） | ☐ |

D3 与 D4 是这一层最值钱的两条：一个证明不幻觉，一个证明不越权。

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |

## F. AI 能力层：写回与审批

| 编号 | 操作 | 期望 | 结果 |
| --- | --- | --- | --- |
| F1 | 让助手「给 po-0002 加一条备注」 | 低风险动作 `append_note` 执行，ERP 里该单据的备注**追加**成两行（不覆盖原备注） | ☐ |
| F2 | 让助手「把这张单推进到已确认」 | 高风险动作进审批队列，**不自动执行**，人工点通过后才生效 | ☐ |
| F3 | 回到 ERP 审计页 | 出现 AI 写回记录：`source=ai`、`actor_id=ai-agent`、`actor_kind=service` | ☐ |
| F4 | 把 `AICRM_ACTION_DRY_RUN=true` 重启后重发 F1 | 动作只被记录、不落到 ERP（ERP 数据不变） | ☐ |

## H. 已知短板：不要当 bug 报

| 编号 | 现象 | 说明 |
| --- | --- | --- |
| H1 | 问「未结应收应付一共多少」答不出来 | 检索按块召回，做不了求和。口径值在 `GET /api/v1/stats/overview` 里（应 76800 / 付 86000），加只读 stats 工具是 P2 待办 |
| H2 | 问「低库存有哪些」答不出具体条数 | 同上，`low_stock_count=1` 已在统计接口里 |
| H3 | 不配 `AICRM_API_TOKEN` 时任何人可调 `/api/v1` | 开发形态。生产必须配 token，且 `AICRM_ENV=prod` 时进程会强制要求（见 go-live-checklist.md §2） |
